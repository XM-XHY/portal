# 服务等级目标（SLO）

> 审查阻断项 **PF-01** 修复文档。定义可量化、可观测、可回归门禁化的服务等级目标。
> 适用系统：企业网站制作平台（Next.js 14 App Router + TypeScript）。
> 本文件为「目标与口径」定义；基线测量方法与阈值见 [`perf/baseline.md`](./perf/baseline.md)，压测骨架见 [`../tests/perf/load-baseline.mjs`](../tests/perf/load-baseline.mjs)。

---

## 1. 范围与口径

| 维度 | 口径 |
|------|------|
| 测量窗口 | 滚动 30 天；周报取近 7 天 |
| 错误预算周期 | 30 天（与月度可用性一致） |
| 成功请求定义 | HTTP 2xx/3xx，且业务层未抛出未捕获异常；支付回调以「正确落库 + 正确回包」为成功 |
| 统计分位 | P50 / P95 / P99（去除建连前的 DNS/TLS 预热样本，前 30s 不计） |
| 资源水位红线 | CPU < 70%、内存 < 80%、DB 连接池使用 < 85%（超出即触发扩容评估） |

---

## 2. 核心 SLO 指标

| 编号 | 指标 | 目标 | 测量点 | 备注 |
|------|------|------|--------|------|
| SLO-1 | **核心下单接口 P95 延迟** | < 800 ms | `POST /api/orders`（创建订单 + 渲染支付页） | 不含第三方支付网关往返；网关调用已独立超时（见 SLO-4） |
| SLO-2 | **支付回调处理 P95 延迟** | < 1 s | `/api/pay/callback/*` → `verifyCallback` → `markOrderPaid` 全链路 | 含验签 + 解密 + 落库；见 `lib/payment.ts` / `lib/orders.ts` |
| SLO-3 | **查单 / 查退款读路径 P95 延迟** | < 1.2 s | `queryOrder` / `queryRefund`（含 5s 超时 + 幂等重试） | 见 `lib/payment.ts` |
| SLO-4 | **外部支付网关调用超时** | 单跳 ≤ 5 s，读操作最多重试 2 次（指数退避 200/400ms） | 微信 V3 / 支付宝网关全部出向请求 | 写操作（下单/退款）**只超时、不重试**，防重复扣款（PF-02） |
| SLO-5 | **服务可用性** | ≥ 99.5%（月度） | 全站 2xx/3xx 占比，排除 4xx 客户端错误 | 对应错误预算 ≈ 3.6 小时/月 |
| SLO-6 | **过载限流正确性** | 触发限流时返回 **429**（非 5xx）且带 `Retry-After` | `lib/rate-limit.ts` 保护的接口 | 限流是「显式拒绝」而非「静默放行 / 静默失败」（RL-02） |
| SLO-7 | **支付配置自检（certCheck）P95** | < 2 s | `selfCheck()` 中微信证书接口连通性探测 | 失败须显式报错，不得误报「可用」 |

---

## 3. 错误预算与告警

- **可用性错误预算**：30 天内允许的不可用时间 = `(1 - 0.995) × 43200 min ≈ 216 min`。
- **预算消耗告警**：
  - 消耗 ≥ 25% → 企业微信/邮件通知值班（黄色）
  - 消耗 ≥ 50% → 升级 + 冻结非必要发布（橙色）
  - 消耗 ≥ 90% → 暂停发布、启动复盘（红色）
- **延迟 SLO 违规**：连续 10 分钟 P95 超阈值即告警，30 分钟超阈值即升级。

---

## 4. 回归门禁（CI / 发布卡点）

| 门禁 | 触发点 | 通过标准 |
|------|--------|----------|
| 类型与构建 | PR / 每次提交 | `npx tsc --noEmit` 通过；`next build` 成功 |
| 单元/集成 | PR | `vitest` 全绿；覆盖率不下降超 2% |
| 压测基线（隔离环境） | 发布前 | `tests/perf/load-baseline.mjs` 在阶梯加压下 P95 不超 SLO-1/SLO-3，错误率 < 0.5% |
| 混沌演练 | 每月 + 重大变更 | `tests/chaos/chaos-cases.md` 用例全部通过，恢复时长达标 |
| 限流正确性 | 发布前 | 过载下确认返回 429 而非 5xx（SLO-6） |

> 注：压测与混沌**禁止在生产环境直接执行**，必须在隔离的 standalone / mock 环境跑（见 baseline.md 与 chaos-cases.md 的「环境隔离」声明）。

---

## 5. 依赖与责任边界

- **本服务可控**：下单、回调处理、限流、自检、超时/重试/熔断原语（`lib/http.ts`）。
- **外部不可控**：微信/支付宝网关、上游 DNS、网络分区。对这些仅能「快速失败 + 显式报错 + 不静默降级」，不承诺其可用性，但承诺**超时受控**（SLO-4）且**失败可见**（RL-02）。
- **回退原则（RL-02）**：任何外部依赖失败都不得回落到「免费放行 / 默认成功 / 吞掉异常」。支付相关失败必须向上抛出并由调用方显式处理（如订单保持 `pending`，等待用户/运维介入）。
