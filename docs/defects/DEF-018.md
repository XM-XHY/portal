# DEF-018 · 支付回调无重放窗口 + 金额校验可跳过

- **来源缺陷编号**：SEC-05（最终报告 §7.6【阻断】）
- **严重度**：阻断
- **负责域**：安全（关屿）
- **关联修复方案引用**：报告 §7.6 ③

## 问题描述
回调验签正确但无时间戳新鲜度窗口、无 nonce / notify_id 去重；`verifyCallback` 金额缺失返 `amountFen=0`，`markOrderPaid` 仅 `>0` 比对 → 0 / 负数 / undefined 跳过金额校验直接置 paid；`mock-notify` 不传金额命中 undefined 分支且无鉴权 / 限流，生产误配 `PAY_PROVIDER=mock` 可任意置 paid。

## 复现 / 证据
- **测试 bug 点（文件:行号）**：
  - `lib/payment.ts:209-241,451-468`
  - `lib/orders.ts:131-151`
  - `app/api/pay/mock-notify/route.ts:10,18`
  - `callback/wechat/route.ts:16-25`、`refund/wechat/route.ts:47-52`
- **现象**：金额校验可被绕过。

## 影响
伪造 / 篡改 / 重放 / 金额不符导致资损。

## 关联修复方案
`verifyNotify` 加 `|now-timestamp|<=300s` + nonce 去重；`markOrderPaid` 把未携带金额视为拒绝：`undefined||<=0||!==o.amountFen` → null 且金额必填；`mock-notify` 加 `NODE_ENV!=="production"` 硬隔离 + 鉴权 + 限流；退款缺 `amount.refund` 拒绝；状态迁移改条件写；CI 用测试商户夹具覆盖合法 / 篡改 / 重放 / 金额不符 / 过期 / 重复 / 退款幂等。

## 验证关闭
- **验证方式**：测试商户夹具 + 本地 mock（真实沙箱另授权）。
- **通过标准**：金额不符/伪造 FAIL 且仍 pending，重放不改订单与权益，生产 provider 下 mock-notify 恒 403。
- **状态**：**已关闭**
- **验证人 / 日期 / 结果**：专家团（自动化实测） · 2026-11-05 · `tests/unit/orders.test.ts` 15 用例：金额缺失/0/负数/NaN/不一致全部拒绝且订单保持 pending；重放同一回调幂等且不刷新 paidAt；mock-notify 在非 mock 通道恒 403；已付订单交易号不一致仅告警不改写。
