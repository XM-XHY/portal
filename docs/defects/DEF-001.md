# DEF-001 · P0 核心纯函数零用例零断言

- **来源缺陷编号**：U-01（最终报告 §7.1【阻断】）
- **严重度**：阻断
- **负责域**：单元·组件级（苏雅）
- **关联修复方案引用**：报告 §7.1 ③

## 问题描述
`lib/` 下 P0 级纯函数 / 状态机分支（支付、权益、鉴权、限流、哈希等）全部无任何隔离单元用例与断言，回归只能靠人工点。

## 复现 / 证据
- **测试 bug 点（文件:行号）**：
  - `lib/pay-grant.ts`、`pay-access.ts`、`work-plans.ts`、`work-db.ts`、`work-session.ts`、`rate-limit.ts`、`cloudbase-pg.ts`、`orders.ts`、`schedule-engine.ts`、`balance-engine.ts` —— 导出纯函数/状态机分支无用例。
  - 关键行：`lib/pay-grant.ts:47,64,84`；`lib/work-db.ts:73,79,92,98,187,202,334`；`lib/orders.ts:57,131,164,177,212`。
  - `package.json:5-13` 无 `test` 脚本。
- **现象**：`package.json` 无 test 脚本；全仓无 `*.test.*` / `*.spec.*`。

## 影响
支付 / 权益 / 鉴权 / 限流回归无自动化网，覆盖率与变异测试无基座，极易引入资损级回归且不可被发现。

## 关联修复方案
引入 Vitest + `test` / `test:coverage`；按边界表逐文件补强断言用例（P0 优先）。应有用例：
`verifyGrant_expired_returnsNull`、`requirePaidAccess_paidMode_unpaidOrder_403`、`capacityOf_余数分配`。

## 验证关闭
- **验证方式**：`vitest run` + 覆盖率报告。
- **通过标准**：用例全绿，P0 分支覆盖率 ≥90%，断言为精确值断言（非恒真）。
- **状态**：**已关闭**
- **验证人 / 日期 / 结果**：专家团（自动化实测） · 2026-11-05 · `npx vitest run` 10 个文件 / 70 用例全绿；纳入覆盖统计的 8 个 P0 模块合并覆盖率 lines 76.27% / branch 81.77% / funcs 84.61%，均高于阈值(70/70/60/70)。
