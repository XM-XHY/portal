# DEF-022 · QA 流程关键环节全零，构建期主动关闭 ESLint（F-01）

- **来源缺陷编号**：F-01（最终报告 §7.8【阻断】）
- **严重度**：阻断
- **负责域**：流程·度量·代码审查（何序）
- **关联修复方案引用**：报告 §7.8 ③（本交付即该修复方案的最小闭环落地）

## 问题描述
QA 流程关键环节全零：无 CI / 流水线 / PR 模板 / CODEOWNERS / 缺陷闭环 / TESTING / SECURITY / CHANGELOG / 准出条件；`package.json:5-13` 无测试脚本；`next.config.mjs:18-20` `eslint.ignoreDuringBuilds:true` 且注释自认「演示项目跳过 ESLint 阻塞」；部署后验证仅两份人工清单无断言 / 退出码 / 留痕。

## 复现 / 证据
- **测试 bug 点（文件:行号）**：
  - `package.json:5-13`（无测试脚本）
  - `next.config.mjs:18-20`（`eslint.ignoreDuringBuilds:true`）
  - 缺 `.github/workflows/`、`pull_request_template.md`、`CODEOWNERS`、`TESTING.md`、`SECURITY.md`、准出条件文档
- **现象**：push 即上线，无评审 / 门禁 / 准出 / 缺陷闭环。

## 影响
无质量门禁，阻断级问题（含资损级安全项）可随 push 直接进入生产。

## 关联修复方案（本交付已落地）
最小闭环八件事：
1. 建 `ci.yml`（tsc + lint + 测试 + 覆盖率，失败阻断）—— **已完成**
2. 补 `.eslintrc.json` 并单列 lint，不依赖 build（移除对 `ignoreDuringBuilds` 的依赖）—— **已完成**
3. 建 PR 模板 / CODEOWNERS / CONTRIBUTING / TESTING / SECURITY —— **已完成**
4. `docs/defects/DEF-<nn>.md` 缺陷单（无验证关闭不得关闭）—— **已完成（DEF-001…022）**
5. `test:smoke` / `test:regression` 入口 + `tests/RESULTS.md` —— **待同事补脚本（DEPENDENT）**
6. `docs/RELEASE-GATE.md` 准出条件 —— **已完成**
7. 后续：覆盖率阈值、质量指标看板（缺陷密度 / 逃逸率 / 回归率）

> 注意：`next.config.mjs` 中的 `eslint.ignoreDuringBuilds:true` **仍保留**（任务要求不编辑业务源文件 / next.config）；本方案通过 CI 中**独立运行 `npx eslint .`** 来覆盖 lint，而不是依赖 `next build`。如需彻底移除该构建期关闭项，应单独变更 `next.config.mjs`（非本次范围）。

## 验证关闭
- **验证方式**：CI 注入类型错误 / 缺 alt / 断言失败 → 观察是否红灯阻断；抽历史缺陷查验证关闭字段。
- **通过标准**：CI 在类型错误 / lint error / 测试失败时红灯阻断；缺陷单验证关闭字段有回填且未经回填不得关闭。
- **依赖**：同事补齐 eslint / vitest 依赖与用例后，CI 才能全绿（见「遇到的坑」）。
