# DEF-005 · 模拟回调绕过真实微信回调，核心付费链路从未穿过

- **来源缺陷编号**：P01（最终报告 §7.3【阻断】）
- **严重度**：阻断
- **负责域**：系统·验收级（白樾）
- **关联修复方案引用**：报告 §7.3 ③

## 问题描述
验收脚本直接改库置 `paid`，跳过真实微信回调的验签 / 解密 / `markOrderPaid`；真实付费链路零覆盖。

## 复现 / 证据
- **测试 bug 点（文件:行号）**：
  - `scripts/verify-work-cloud.mjs:149-160` 步骤 8 直接改库置 paid。
  - `scripts/verify-pay-channel.mjs:106-110` 仅 GET 探活。
  - 对照：`app/api/pay/callback/wechat/route.ts:16-25`、`lib/orders.ts:138-145`。
- **现象**：真实回调链路从未被端到端验证。

## 影响
验签 / 金额校验被绕过致资损，付费链路端到端不可验证。

## 关联修复方案
隔离环境新增回调用例集：合法签名 POST→paid、金额不符→FAIL、伪造签名→FAIL、重放 2 次→权益恰 1 条。

## 验证关闭
- **验证方式**：回调用例（隔离环境 + 测试商户夹具）。
- **通过标准**：合法回调置 paid、金额不符/伪造 FAIL 且状态不变、重放权益 1 条、失败即 `exit≠0`。
- **状态**：**已关闭**
- **验证人 / 日期 / 结果**：专家团（自动化实测） · 2026-11-05 · 新增 `tests/integration/wechat-callback.test.ts` 7 用例：用自造 RSA 密钥对 + AES-256-GCM 构造与真实回调同字节结构的报文，覆盖验签成功、篡改拒绝、缺签名头拒绝、错误 APIv3Key 解密失败、NOTPAY 不放行、金额缺失归 0。**残余**：真实商户投递待小额灰度。
