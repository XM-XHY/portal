# DEF-002 · 并发/幂等读改写竞态无并发用例

- **来源缺陷编号**：U-04（最终报告 §7.1【阻断】）
- **严重度**：阻断
- **负责域**：单元·组件级（苏雅）
- **关联修复方案引用**：报告 §7.1 ③

## 问题描述
订单 / 权益 / 限流的读改写与并发路径无并发用例，状态可能在中高并发下被覆盖或重复发放。

## 复现 / 证据
- **测试 bug 点（文件:行号）**：
  - `lib/orders.ts:109-116` 读全表改一条写全表（无 CAS）。
  - `lib/data/supabase-repo.ts:278` 无 CAS upsert。
  - `lib/orders.ts:138` `markOrderPaid` 对 `paidAmountFen=0/负数/undefined` 跳过金额校验。
  - 权益发放靠唯一约束回查；限流双层合并写失败静默降级。
- **现象**：存在并发写路径但零并发断言。

## 影响
并发下订单状态可能被覆盖、权益可能被重复发放，直接导致资损。

## 关联修复方案
mock 双快照 `Promise.all` 并发断言；补 `paidAmountFen` 边界表；订单更新改条件写 / 版本号；限流写失败不可静默降级。

## 验证关闭
- **验证方式**：并发用例（100 次并发或更高）。
- **通过标准**：并发 100 次最终状态恒为期望、权益表 `order_id` 恒唯一、限流第 `limit+1` 次恒 429。
- **状态**：**部分关闭**
- **验证人 / 日期 / 结果**：专家团（自动化实测） · 2026-11-05 · `markOrderPaid` 重放幂等、create `reqId` 幂等、claim 同账号幂等均已有精确断言用例。**残余**：多实例真并发竞争（同一毫秒双写）未实测，需隔离环境压测，保留开放。
