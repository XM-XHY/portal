# DEF-003 · 契约资产为零，且 create 幂等键已实际漂移

- **来源缺陷编号**：P1（最终报告 §7.2【阻断】）
- **严重度**：阻断
- **负责域**：集成·接口级（柯砚）
- **关联修复方案引用**：报告 §7.2 ③

## 问题描述
无接口契约资产；同时 `/api/works/pay/create` 的 `reqId` 幂等键在提供端被忽略，已实际漂移，重试 / 双击会产生多笔真实订单。

## 复现 / 证据
- **测试 bug 点（文件:行号）**：
  - 提供者：`app/api/works/pay/[action]/route.ts:38-88` 仅取 `plan/client`，忽略 `reqId`，每次新建并调网关预下单。
  - 消费者：`assets/works/quanke.html:3511-3537`、`scripts/verify-work-cloud.mjs:135`。
  - 契约目录缺失（`contracts/` 不存在）。
- **现象**：前端/脚本以为有幂等，后端没有。

## 影响
跨端漂移：重试 / 双击产生多笔真实订单，资损且对账困难。

## 关联修复方案
建 `contracts/` 用 Pact 生成 `works-pay.json`；CI `pact-verify` + 破坏性变更检测；`create` 落地 `reqId` 幂等或删除该字段；补 OpenAPI 3.1 + Schemathesis。

## 验证关闭
- **验证方式**：契约验证 + 幂等用例。
- **通过标准**：同一 `reqId` 两次 POST 返回同一 `orderId` 且库内订单数 = 1；删除字段 `days` 时契约验证必须失败。
- **状态**：**已关闭**
- **验证人 / 日期 / 结果**：专家团（自动化实测） · 2026-11-05 · `node tests/contract/verify.mjs` 15/15 通过；create 分支已落地 `reqId` 幂等（落于 `order.work.reqId`，按 userId+client+reqId+未完成 复用），契约漂移已消除。
