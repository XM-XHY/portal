# 发布准出条件（RELEASE-GATE.md）

> 归属：流程·度量·代码审查域（何序）。状态：初始版。
> 原则：**门禁不通过不得发布；阻断级问题清零前不得上线。**

## 一、硬性准出条件（任一不满足即禁止发布）

### 1. CI 门禁全绿
- [ ] `npx tsc --noEmit` 通过（无类型错误）
- [ ] `npx eslint .` 无 error（warn 需逐条说明，不得批量静默）
- [ ] `npx vitest run` 通过（用例全绿，P0 分支覆盖率达标）
- [ ] 覆盖率报告可复现（若已接入）

### 2. 缺陷清零
- [ ] 所有**阻断级**缺陷（`docs/defects/DEF-*.md`）已修复且「验证关闭」字段**已回填**。
- [ ] 严重级缺陷已排期或在本轮一并关闭；不得带未登记的严重问题上线。
- [ ] 每个修复 PR 已在 PR 模板中关联对应 DEF 编号。

### 3. 安全红线（fail-close）
- [ ] 付费墙 / 鉴权在依赖故障时不静默放行（见 DEF-013、DEF-014）
- [ ] 支付链路：签名、金额、重放、nonce 校验齐备（见 DEF-018）
- [ ] 无写死密钥 / 盐 / token；密钥全部环境变量注入且生产已配置（见 SECURITY.md）
- [ ] 含用户态接口已 `no-store`（缺口见 DEF-no-store.md，敏感路由优先清零）

### 4. 评审与变更留痕
- [ ] PR 已通过 CODEOWNERS 指定 reviewer 审批
- [ ] 变更含数据库连接 / DDL 时，已附迁移脚本与回滚预案
- [ ] 部署后冒烟（`test:smoke`）通过且退出码非 0 即阻断

## 二、发布前检查单（发布负责人签字）

| 项 | 结果 | 负责人 / 时间 |
|---|---|---|
| CI 全绿 | ☐ | |
| 阻断缺陷清零 | ☐ | |
| 安全红线通过 | ☐ | |
| 评审通过 | ☐ | |
| 回滚预案就绪 | ☐ | |

## 三、回滚与发布后验证

- 任何发布须有**回滚预案**（CloudBase 版本回退 / Vercel 回滚 / DNS 切回）。
- 发布后 30 分钟内完成核心链路冒烟与付费链路抽检；异常立即回滚并登记缺陷。
- 真实支付请在隔离/小额环境下走一笔验证后台权益发放（见 overview 后续注意）。

## 四、降级声明

- 性能 / 可靠性 / 兼容性 / 无障碍等维度的「未发现 / 待核实」项，须补实测证据后复评，不得仅凭静态审查放行。
- 本准出门禁为从严口径；一票否决任何阻断级问题。
