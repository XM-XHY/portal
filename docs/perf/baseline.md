# 性能基线与容量说明

> 审查阻断项 **PF-01** 配套文档（性能资产 / 基线 / 容量）。定义基线「怎么测、测什么、预期阈值是多少」，
> 以及「当前容量能支撑多少业务量」的结论口径。压测骨架见 [`../../tests/perf/load-baseline.mjs`](../../tests/perf/load-baseline.mjs)。

---

## 1. 基线测量方法

### 1.1 环境要求（必须隔离）
- **绝不**在生产直接加压。使用与生产的同构镜像（Next.js standalone 或 `next start`）跑在隔离机器/命名空间。
- 数据库、对象存储、缓存使用**影子/副本**或独立实例，避免污染真实订单与余额数据。
- 外部支付网关用 **mock 端点**（本地 HTTP 服务返回固定延迟与状态码），不触达微信/支付宝真实接口。
- 监控：Prometheus + 应用内 `performance.mark` / 自定义计时；至少采集 P50/P95/P99 与错误率、QPS、资源水位。

### 1.2 阶梯加压步骤
1. 预热 30s（不计入统计）。
2. 从 **10 RPS** 起步，按 `10 → 30 → 60 → 100 → 150 → 200` 阶梯递增，每档持续 **120s**。
3. 每档记录：实际吞吐、P95 延迟、错误率（含 429/5xx/超时）、CPU/内存/DB 连接池水位。
4. 到达「P95 超 SLO 阈值」或「错误率 > 0.5%」或「资源水位触红线」即停止，记录拐点。

### 1.3 关键链路（必须覆盖）
| 链路 | 入口 | 说明 |
|------|------|------|
| 下单 | `POST /api/orders` | 创建订单 + 生成支付二维码（走 mock 支付通道） |
| 支付回调 | `POST /api/pay/callback/*` | 验签 + 解密 + `markOrderPaid` 落库 |
| 查单 | `queryOrder`（mock 网关） | 幂等读，含 5s 超时 + 重试 |
| 限流 | 高频打同接口 | 验证返回 429（SLO-6） |

## 2. 预期阈值（基线目标）

> 以下公式给出「目标容量」估算口径；真实数字以隔离环境实跑为准（本仓库未内置历史基线数据）。

| 指标 | 预期阈值 | 超限动作 |
|------|----------|----------|
| 下单接口 P95 | < 800 ms（SLO-1） | 扩容实例 / 优化 DB 写入 |
| 回调处理 P95 | < 1 s（SLO-2） | 优化解密/落库批处理 |
| 读路径 P95 | < 1.2 s（SLO-3） | 加缓存 / 连接池调优 |
| 单实例安全水位 QPS | 见下方容量测算 | 触顶前水平扩容 |

---

## 3. 容量测算（口径）

**经验公式（Little's Law 简化）**：
```
最大可持续 QPS ≈ 并发上限 / P95 延迟(s)
```
- 设单实例 Node 事件循环可稳定支撑的并发请求数 `C`（建议取压测拐点，初值 200）。
- 下单 P95 ≈ 0.8s → 单实例容量 ≈ 200 / 0.8 = **250 QPS**（理论值，需实跑校正）。
- 留 30% 余量 → 生产单实例建议承载 **≤ 175 QPS**。

**结论口径（待实跑填充真实值）**：
- 当前（未跑基线）结论：**容量未知，需按 §1 在隔离环境跑 `load-baseline.mjs` 后回填本表**。
- 回填项：单实例拐点 QPS、P95、错误率、各资源水位，以及「达到 SLO-5 99.5% 可用性所需的实例数」。

---

## 4. 瓶颈定位手段（压测发现问题后）
- **CPU/事件循环**：Node `--prof` 火焰图（`0x` / `clinic.js flame`）。
- **慢查询**：DB 慢日志 + `EXPLAIN`；关注 `orders` 表按 `id` / `status` 的索引。
- **链路追踪**：在 `lib/http.ts` 的出向请求前后打 `performance.mark`，串联 `traceparent`。
- **外部依赖**：区分「本服务耗时」与「网关往返耗时」（网关已在 `lib/payment.ts` 处 5s 超时隔离）。

---

## 5. 回归门禁
- 每次发布前在隔离环境跑 `load-baseline.mjs`，对比上一次基线：
  - P95 劣化 > 20% 或错误率 > 0.5% → 阻断发布。
  - 容量（拐点 QPS）下降 > 15% → 提示复盘。
- 基线结果落库到 `docs/perf/` 下带日期的报告（本仓暂未生成；首次实跑后补充）。

> ⚠️ **未实测声明**：截至本文件撰写，性能基线**尚未在隔离环境实跑**，上述阈值与容量为设计值与测算口径，非实测结论。
