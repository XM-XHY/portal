## 用例总览

| 编号 | 场景 | 故障类型 | 预期恢复时长 | 关键观测 |
|------|------|----------|--------------|----------|
| CH-1 | 数据库不可用 | 断库（连接拒绝 / 熔断） | < 30s 自动降级到错误页 / 排队 | DB 连接错误率、订单创建失败率、是否返回 5xx 而非静默空数据 |
| CH-2 | 支付网关超时 | 网络分区 / 网关挂起 | 读 ≤ 5s×3 超时返回失败；写 ≤ 5s 超时返回失败 | 出向请求超时率、是否触发 `TimeoutError`、是否**未**重复扣款 |
| CH-3 | 支付回调重放 | 重放攻击 / 重复投递 | 幂等：重复回调**不改写**已支付金额 | `markOrderPaid` 实付金额一致性校验、重复处理日志 |
| CH-4 | 进程重启 | 实例崩溃 / 滚动发布 | 无状态实例 < 10s 恢复；有状态会话 < 30s | 重启期间错误率、已下单未支付订单是否可继续 |
| CH-5 | 限流击穿 | 突发流量 | 立即返回 429（非 5xx） | 限流命中率、`Retry-After` 头、下游是否被打挂 |

## CH-1 数据库不可用

- **注入方式**：将 `DATABASE_URL` 指向一个不可达地址，或在隔离环境用 `iptables`/`tc` 丢弃到 DB 的流量；也可在测试库直接停服。
- **预期行为**：
  - 订单创建 / 查询接口快速失败（受 DB 连接超时约束），返回明确错误（5xx 或友好错误页），**不得**返回「静默空列表 / 假装成功」。
  - 连接池耗尽时不应无限堆积请求（结合 `lib/rate-limit.ts` 限流兜底）。
- **恢复**：DB 恢复连通后，应用自动重连，无需重启（确认连接池 `max` 与重试配置）。
- **观测指标**：`db_connection_errors`、`orders_create_error_rate`、P95 延迟、是否出现「空数据但 200」的反模式。

---

## CH-2 支付网关超时（网络分区）

- **注入方式**：用 mock 网关返回**永不响应**的 socket（或 `tc netem delay 9999ms`），模拟微信/支付宝不可达。
- **预期行为**：
  - **读操作**（查单 / 查退款 / 证书自检）：`lib/payment.ts` 经 `fetchWithTimeout`（5s）+ `withRetry`（指数退避 200/400ms）后**显式抛出 `TimeoutError`**，不静默成功。
  - **写操作**（下单 / 退款）：仅 5s 超时、**不重试**，避免重复扣款；失败后订单保持 `pending`，由用户/运维介入。
  - 任何路径都**不得**回落到「免费放行 / 默认成功 / 吞异常」（RL-02）。
- **恢复**：网关恢复后，查单等读路径自动恢复；写路径需重新发起（幂等键 `out_trade_no` / `out_refund_no` 防重）。
- **观测指标**：出向 `gateway_timeout_count`、`TimeoutError` 计数、重试次数分布、写操作「零重复扣款」对账。
- **自动化验证**：见 `network-partition.stub.mjs`（mock 挂起 → 断言抛 `TimeoutError` 且未静默成功）。

---

## CH-3 支付回调重放

- **注入方式**：将同一笔已成功回调的报文（含相同 `out_trade_no` + `transaction_id`）再次 POST 到 `/api/pay/callback/*`。
- **预期行为**：
  - `lib/orders.ts` 的 `markOrderPaid` 校验回调实付金额与下单一致（SEC-05，本次未改动其语义）。
  - 重复回调不得改写已支付订单的实付金额 / 状态（幂等），并明确记录「重复投递」。
- **恢复**：即时（幂等处理），无副作用。
- **观测指标**：`callback_replay_count`、`markOrderPaid` 金额不一致告警、重复处理日志。

---

## CH-4 进程重启

- **注入方式**：`kill -9` 单实例（standalone），或触发一次滚动发布。
- **预期行为**：
  - 无状态接口在实例起来后立即可用；进行中的支付轮询（前端轮询 `queryOrder`）可重试恢复。
  - **不丢失**已下单未支付的订单（状态在 DB，不在内存）。
- **恢复**：< 10s（无状态）/ < 30s（含连接池预热）。
- **观测指标**：重启窗口错误率、重启后首请求 P95、进行中订单可继续率。

---

## CH-5 限流击穿

- **注入方式**：用 `load-baseline.mjs` 或简单脚本以远超阈值的 RPS 打同一受保护接口。
- **预期行为**：`lib/rate-limit.ts` 立即返回 **429 + `Retry-After`**，下游不被打挂（SLO-6）。
- **恢复**：流量回落后自动恢复。
- **观测指标**：`rate_limit_hits`、429 占比、下游 5xx 是否受控。

---

## 演练节奏与门禁

- **频率**：每月一次常规演练 + 重大变更（支付/订单/限流相关）前必跑 CH-2 / CH-3。
- **门禁**：CH-1~CH-5 全部「预期行为」达成才算通过；任一出现「静默降级 / 重复扣款 / 金额不一致」即阻断发布。
- **记录**：每次演练存档（日期、注入参数、实测恢复时长、观测截图），回填本文件表格。
