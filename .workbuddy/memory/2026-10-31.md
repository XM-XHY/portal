### 阶段四（接入 Supabase + 真实 Bing/LLM 检索）
目标：把自托管 JSON 存储与示例搜索升级为生产级可插拔架构。
- **可插拔数据层 lib/data/**：
  - types.ts（Repo 统一接口 + 领域类型）、hash.ts（密码哈希，SALT 共用）、defaults.ts（站点/管理员/资讯默认值）。
  - json-repo.ts：原 store.ts 的文件存储实现提取至此（本地/自托管零依赖）。
  - supabase-repo.ts：Supabase 实现（@supabase/supabase-js，服务端用 SERVICE_ROLE_KEY 直连，getSite 失败时降级默认值保官网不 500；首次访问自动 seed 管理员与站点默认值）。
  - index.ts：按环境变量选择——配置了 SUPABASE_URL+SUPABASE_SERVICE_ROLE_KEY 走 Supabase，否则走 JSON。
  - lib/store.ts 改为薄委托层（保持全部原函数签名，路由/组件无需改动即可切换）。
  - session.ts / admins 路由 / login 路由 由 readDb() 改为 getAdmins()。
- **Supabase 表结构**：supabase/schema.sql（site_info/admins/leads/contents/search_logs/audit_logs + 种子，含预计算管理员哈希）。
- **真实全网检索 lib/search.ts**：
  - 优先级：Bing(BING_API_KEY) → SerpAPI(SERPAPI_KEY) → 内置示例(mock)，失败自动降级。
  - 新增 LLM 摘要：配置了 LLM_API_KEY（OpenAI 兼容，默认 gpt-4o-mini，可换 DeepSeek/通义/自建网关）时，对真实检索结果生成"带引用编号的摘要 + 来源清单"，9s 超时/失败不影响结果展示。
  - 类型新增 summary / sources；前端 ExploreClient 在结果列表上方展示 AI 摘要卡片与来源引用 chips。
- **配置**：.env.example 补全 SUPABASE_URL/SERVICE_ROLE_KEY/ANON_KEY、LLM_API_KEY/BASE_URL/MODEL、保留 BING_API_KEY/SERPAPI_KEY；package.json 增加 @supabase/supabase-js。
- **验证**：tsc --noEmit 通过；dev 全链路（页面 200、双账号登录、站点 PUT+RBAC 403、搜索 mock 返回 5 条无 summary、线索增查、审计 200/403、内容 CRUD）全部通过。Supabase/Bing/LLM 真实调用需用户提供密钥后生效（本机无密钥，走兜底）。
- **联调说明**：启用 Supabase 时，先执行 supabase/schema.sql，再在 .env 填 SUPABASE_URL + SERVICE_ROLE_KEY 重启即可，代码零改动。启用真实检索同理填 BING_API_KEY；启用 AI 摘要填 LLM_API_KEY。
